# 06. 検索の評価セットと評価コマンド

- ブランチ: `feat/search-eval`
- 前提: 05 がマージ済み（辞書に300〜500項目が入っている）
- 参照: 共通の決まりは [README.md](README.md)

## 目的

「あいまいな読みでも正しいハングルが候補に出るか」を、感覚ではなく **数字で測れる** ようにします。
07・08 の改善は、すべてこの数字で良し悪しを判断します。このPRでは検索の処理は変えません。

## 背景: なぜ今の検索では足りないのか

今の検索は、ひらがなに正規化した読みを `pg_trgm` のトライグラム類似度で比べています。
語尾の付け足しや1文字の聞き間違いには強い一方で、**日本人の耳が揺れやすい音の違い**には弱いです（PostgreSQL 16、`locale=C.UTF-8` での実測）。

| 辞書の読み | うろ覚えの読み | 類似度 |
|---|---|---|
| けんちゃな | けんちゃなよ | 0.63 |
| あんにょん | あんによん | 0.33 |
| こまうぉ | ごまうぉ | 0.25 |
| おっぱ | おぱ | 0.17 |
| ちんちゃ | じんじゃ | **0.00**（まったくヒットしない） |

原因は、トライグラムが「文字が同じか」しか見ず、「ち」と「じ」が音として近いことを知らない点です。
韓国語の ㄱ・ㄷ・ㅂ・ㅈ は、語頭と語中で「カ／ガ」「チ／ジ」と聞こえ方が変わるため、ここは避けて通れません。

## 2. 評価セット

`db/seed/eval.json`

```json
[
  { "input": "じんじゃ", "expected_hangul": "진짜", "note": "語頭の濁り" },
  { "input": "ごまうぉ", "expected_hangul": "고마워", "note": "語頭の濁り" },
  { "input": "サランヘヨ", "expected_hangul": "사랑해요", "note": "語尾つき" },
  { "input": "saranghe", "expected_hangul": "사랑해", "note": "ローマ字" }
]
```

- 100件程度。カタカナ・ひらがな・ローマ字を混ぜる
- 揺れの種類（`note`）をまんべんなく入れる: 語頭の濁り、ッの有無、小さい字の有無、パッチムの聞き落とし（かむさ／かんさ）、語尾の付け足し・脱落、母音の聞き違い（ㅓ／ㅗ）、ローマ字の綴り違い（jj／j、eo／o）
- `expected_hangul` は、辞書に投入済みの単語から選ぶ
- 08 では、評価セットの入力を読みの別表記にコピーしないことが求められます。評価が正解の丸暗記を測るだけにならないよう、ここでは別表記のことを考えずに作ってください

🛑 **評価セットをユーザーに確認してもらってください。**

## 3. 評価コマンド

`backend/cmd/evalsearch/main.go` を追加します。

- `DATABASE_URL` のDBに対して、評価セットの全件を `matching.Service` で検索する（**AIフォールバックは無効**にして、DB検索だけの実力を測る）
- 出力: `recall@1`、`recall@8`、揺れの種類（`note`）ごとの `recall@8`、外れた入力の一覧（入力・期待値・実際の上位3件とスコア）
- 終了コード: `-min-recall8` フラグ（既定 0）を下回ったら 1 を返す（CIで使えるようにするため）

今の検索のまま実行し、数値を PR に記録します。これがベースラインです。
