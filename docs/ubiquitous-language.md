# ユビキタス言語一覧（Hangul-me）

プロジェクト全体（企画・設計・実装・UI文言）で用語を統一するための一覧です。
会話の中で新しい概念が出てきたら、都度この表に追記していきます。

運用ルール:
- **ユーザー向けの言葉**列は、UI文言・ドキュメントでユーザーに見せる表現の基準にする
- **開発用語（英語）**列は、DBスキーマ・API・コード上の命名の基準にする（DDDのモデル名と一致させる）
- 一度決めた用語は理由なく言い換えない。呼び方を変えたい場合はこの表を更新してから実装に反映する

## 中核概念

| ユーザーが思い描く言葉 | ユーザー向けの言葉（UI表記） | 開発用語（英語） | 説明 |
|---|---|---|---|
| うろ覚えの韓国語の音 | うろ覚えの読み / 入力した読み | `query` / `input_reading` | ユーザーがカタカナ・ひらがな・アルファベットで入力する、記憶があいまいな読み方 |
| 韓国語の単語・フレーズそのもの | 単語 | `word` / `dictionary_entry` | ハングル・読み・意味・例文をひとまとまりにした辞書上の1エントリ。単語帳に限らず、DBの正規辞書マスタも指す |
| 単語の候補一覧 | 候補 | `candidate` | うろ覚えの読みから検索してヒットした単語の一覧。1件1件を指す場合は「候補」単数 |
| 候補を選んで自分の単語帳に加える行為 | 登録する | `register` | 候補から選択し、ユーザー自身の単語帳（`user_words`）に保存する操作 |
| 自分だけの単語帳 | 単語帳 / 登録単語一覧 | `user_dictionary` / `user_words` | ユーザーが登録した単語の集合。ダッシュボードのメイン画面 |
| 単語1件の詳細を見る画面 | （単語の）個別ページ / 詳細ページ | `word_detail` | ハングル・読み・意味・例文・（将来は復習状況）をまとめて表示する画面 |

## マッチング・検索まわり

| ユーザーが思い描く言葉 | ユーザー向けの言葉（UI表記） | 開発用語（英語） | 説明 |
|---|---|---|---|
| 読み方を入力して単語を探す機能全体 | 単語を調べる | `lookup` | サイドバー・メインボタンで統一した、検索モーダルを開く導線の名称。旧称「候補検索」「新しく調べる」は廃止 |

## アプリ・画面構成

| ユーザーが思い描く言葉 | ユーザー向けの言葉（UI表記） | 開発用語（英語） | 説明 |
|---|---|---|---|
| アプリ全体の名前 | Hangul-me | `app_name` | 「ハングル」+「〜me」の造語。綴りは "Hangul-me" で固定（"Hangle-me" は誤字なので使わない） |
| ログインしていない状態から入る画面 | ログイン / 新規登録 | `sign_in` / `sign_up` | 同一カードをタブで切り替える構成。見出しはログイン時「おかえりなさい」、新規登録時「ようこそ」 |
| ダッシュボードの主要画面（単語帳） | 登録単語一覧 | `word_list_view` | ログイン後のデフォルト表示。ロゴクリックでも戻る |
| 左側の開閉できるメニュー | サイドバー | `sidebar` | 開閉状態を持つ。閉じた状態では各アイコンにホバーでツールチップを表示 |
| 単語を調べるための入力画面 | （単語を調べる）モーダル | `lookup_modal` | オートフォーカス、ネオン風フォーカス演出、リアルタイム候補表示を持つ |
| 操作結果を知らせる一時的な通知 | トースト通知 | `toast` | 画面右下に表示。単語登録完了時などに使用 |

## 学習の記録（分析・可視化）

| ユーザーが思い描く言葉 | ユーザー向けの言葉（UI表記） | 開発用語（英語） | 説明 |
|---|---|---|---|
| グラフで振り返る画面全体 | 学習の記録 | `analytics_view` | 登録単語を集計してグラフで見せる画面。サイドバーの項目名もこれに合わせる |
| 語頭の子音 | 初声 | `initial_consonant` | 先頭音節の子音。互換字母（ㄱ/ㄴ/ㄷ…）で保持。「どの音から始まる単語を拾いがちか」の軸 |
| 語末の子音 | パッチム | `final_consonant` | 末尾音節の終声。無い場合は `has_final_consonant = false` |
| 音節を字母に分解すること | （内部処理、UI上は非表示） | `hangul.Analyze` | ハングルから初声・パッチムを機械的に導出する処理。登録時に1回だけ実行する |
| その単語をどこで知ったか | どこで聞いた？ | `encountered_title` | ドラマ・映画名などの記録。作品別の登録数の集計に使う |
| 個別ページを開いた記録 | （内部処理、UI上は非表示） | `word_view_logs` | 閲覧イベントの生ログ。直近90日のみ保持 |
| 閲覧記録を日ごとにまとめたもの | （内部処理、UI上は非表示） | `user_word_daily_views` | 1単語1日1行の日次集計。恒久保持し、長期の傾向はこちらで見る |
| 生ログを集計へ丸めて古い分を消す処理 | （内部処理、UI上は非表示） | `rollup` | 日次バッチ。冪等で、複数回実行しても結果は変わらない |
| よく調べた単語 | よく調べた単語 | `most_searched` | 選択・登録された回数の多い順。表示しただけの候補は数えない |
| よく見返した単語 | よく見返している単語 | `most_viewed` | 個別ページを開いた回数の多い順。生ログ＋日次集計を合算する |

## 設計・技術用語（開発者間の会話用）

| 用語 | 説明 |
|---|---|
| DDD（ドメイン駆動設計） | domain / usecase / infra / interface の4層構成を採用 |
| Ginkgo | Go言語のBDDテストフレームワーク。usecase〜domain層のテストに使用 |
| NeonDB | サーバーレスPostgres。DB本体。`pg_trgm`・`pgvector`拡張を利用予定 |
| Cloudflare R2 | v2で追加する発音音声ファイルの保管先（S3互換オブジェクトストレージ） |
| Clerk / Clerk Elements | 認証基盤。UIはヘッドレスのClerk Elementsで自前構築し、ブランディング表示を回避 |
| Dev Container | VS Codeの開発コンテナ。Go / Node / Docker / GitHub CLI / Claude Code を同梱 |
| 開発スタック | `docker compose` で同時起動する db / backend / frontend の3サービスの総称 |
| フォルダストラクチャ図 | `docs/folder-structure.md`。ディレクトリ構成と責務の一覧。変更時は必ず更新する |
| 指示書 | `CLAUDE.md`。用語・言語の使い分け・ブランチ運用・ドキュメント更新の決まりごと |
